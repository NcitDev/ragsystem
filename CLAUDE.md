# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with
code in this repository.

**This is a Rust-only project.** It was ported from Python; the Python source
has been removed. Do not add Python back to the runtime, build, or tests. The
migration/parity record is in `docs/rust-migration-plan.md`,
`docs/python-parity-audit.md`, and `docs/benchmark_full_matrix/summary.md`.

## Commands

Everything ships as one binary built from a Cargo workspace. `cargo build
--release -p rag-app` produces `target/release/rag-rs`; installed as `~/.local/
bin/rag`.

```bash
# Build / test / lint
cargo build --release -p rag-app
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --check

# Daemon (the supervised process): Axum HTTP on 127.0.0.1:7890
rag start
rag service install          # systemd user unit (Linux) / launchd agent (macOS)

# Qdrant
rag qdrant-up | qdrant-down | qdrant-status   # Docker container rag-qdrant, or embedded mode

# Index / search / navigate (HTTP clients to the daemon)
rag index [path] [--full] [--lang X] [--name myrepo]
rag search "query" [--repo name] [--top-k N] [--planner fallback|llm|auto]
rag smart-search "question" --repo name
rag resolve Symbol --repo name
rag callers|callees|impact Symbol --repo name
rag ask "question" --repo name
rag tui                      # Ratatui stack dashboard
rag web                      # browser dashboard served at /
```

The daemon **must** be running for `search`, `index`, `resolve`, `ask`, etc.
— they are HTTP clients to `:7890`.

## Architecture

Cargo workspace, one final `rag` binary. Dependency direction:
`contracts <- config/storage/index/retrieval/services/agent <- server <- app`.

- **`rag-app`** — the binary: Clap CLI, Ratatui TUI, `service` (launchd/systemd)
  and Docker-Qdrant management, `migration` shadow/cutover tooling.
- **`rag-server`** — Axum app (`serve`/`router_with_state`), the live retrieval
  pipeline (`retrieval.rs`), the indexing write path (`indexing.rs`), managed
  embedded-Qdrant boot (`qdrant_boot.rs`), and the embedded web dashboard.
  Middleware: per-token rate limit, CSRF origin guard, loopback trusted-host
  check, request logging to `~/.rag/logs/daemon.jsonl`, and a JSON error
  envelope `{error, code, detail}`. State (token, event ring, retrieval
  backend) lives in `ServerState`.
- **`rag-retrieval`** — deterministic scoring, symbol sanity filter, query
  expansion, the `ast-index` CLI bridge (`ast_index.rs`, incl. `_attach_code`
  file-reading spans, `related_files`), and repo-agent planning.
- **`rag-index`** — tree-sitter chunking (`chunker.rs`), metadata enrichment
  (`enrich.rs` kotlin/java, `enrich_python.rs` python `patterns.py` port),
  file discovery (no `.gitignore` filtering — parity with the Python indexer),
  lexical SQLite index, graph structures.
- **`rag-agent`** — the `Planner` trait, agy subprocess adapter (full
  `RETRIEVAL_INSTRUCTIONS`/`SYMBOL_PROMPT` prompts), Rig providers, and the
  deterministic heuristic fallback that must never let planning fail a request.
- **`rag-services`** — Ollama (`embed_query`/`embed_documents` with the two
  Qwen3 instruction prefixes, `chat`) and Qdrant (search/scroll/upsert/count/
  delete, payload filters) HTTP clients.
- **`rag-storage`** — read-mostly SQLite: code index + FTS
  (`search_code_chunks`, `list_code_files`, `related_test_files`), embed cache
  (`EmbedCache`, `{model}:{content_hash}` keys, LE-f32 blobs), repo registry,
  query log, incremental `state.json`.
- **`rag-config`** — deep-merges the embedded `assets/default.toml` with
  `~/.rag/config.toml`; `load_env_files` loads `~/.rag/.env` + project `.env`.

### Config

`qdrant.mode`: `server` connects to `qdrant.url` (Docker via `rag qdrant-up`);
`embedded` makes the daemon download + run a pinned Qdrant child process on the
`url` port with `~/.rag/qdrant_server` storage. Read config via
`rag_config::load_settings`; the packaged defaults are the single source of
truth (`crates/rag-config/assets/default.toml`).

### Indexing invariants

Incremental by git-state + per-file SHA in `~/.rag/repos/<sha>/state.json`
(atomic tmp-then-rename). `chunk_id` = sha256 of `file:chunk_type:start:end`;
Qdrant point IDs are `uuid5(NAMESPACE_DNS, chunk_id)`. A language-filtered run
must not delete other languages' chunks (diff is language-scoped). Per-repo run
lock. `PAYLOAD_INDEXES` in `indexing.rs` is the authoritative filterable-field
list. LOD/summary and vocab *collections* are consumed by search when present
but are not currently generated by the Rust indexer.

### Retrieval invariants

`plan_search` → `SearchPlan {queries, filters, strategy, top_k}` (LLM planner
per `[retrieval_agent]`, else heuristic `fallback_plan`). Four strategies:
`lod_drill` (degrades to hybrid without LOD data), `global`, `graph_walk`
(degrades to hybrid), `hybrid`. Then lexical promotion (FTS, score squash
`0.75·raw/(raw+3)`), symbol sanity filter, weighted scoring. `/smart-search`
adds LLM symbol inference → index grounding → exact resolve → structural
`related` (ast-index) → candidates pagination. No rerank stage (removed).

## Conventions

- Errors: `thiserror` in libraries, `anyhow` only at the `rag-app` boundary.
  Routes map failures to the JSON error envelope; planner/provider failures
  degrade to deterministic results, never a 500.
- Async on the server side (Tokio); blocking SQLite work goes through
  `spawn_blocking`.
- Keep request-model validation (query length, top_k bounds, planner enum) in
  `validate_request_contract` aligned with the FastAPI-compatible 422 shape.
- Every behavior change should keep `cargo test --workspace` green and, for
  retrieval, be checked against `bench/` benchmark artifacts.
